# مستحقات برامج إذاعة وقناة دار الإفتاء الليبية

موقع عربي لإدارة مشاركات المقدمين والشيوخ في إذاعة دار الإفتاء الليبية وقناتها المرئية، ومراجعتها وحساب مستحقاتها الشهرية.

## القنوات والحسابات والأسعار

- يستخدم جميع الموظفين حساب دخول واحداً، ثم يختارون قسم الإذاعة أو القناة المرئية. الصلاحيات والأدوار مشتركة، لكن البرامج والمشاركات والمراجعات والحجوزات والحلقات والأرشيف والتقارير محفوظة لكل قناة على حدة.
- لكل قناة تقويم حجوزات مستقل؛ لذلك لا يمنع حجز موعد في قناة حجز الموعد نفسه في القناة الأخرى.
- تبدأ القناتان بالأسعار نفسها، ويمكن للإدارة العليا تعديل أسعار الساعة لكل قناة بصورة مستقلة:

| نوع البرنامج | المقدم / المقدمة | الشيخ |
|---|---:|---:|
| مسجل | 100 د.ل للساعة | 150 د.ل للساعة |
| مباشر | 40 د.ل للساعة | 75 د.ل للساعة |

- يسجل كل طلب سعر الساعة والمبلغ المحسوب عند إنشائه؛ تغيير السعر لا يعيد احتساب الطلبات السابقة. تُنسب السجلات القديمة التي لا تحمل قناة إلى الإذاعة عند ترقية البيانات.

تُحسب المدة بالدقائق. تضاف أسماء البرامج من حساب الإدارة العليا، ويختار المستخدم البرنامج من القائمة عند التسجيل. يشمل الكشف الرسمي المشاركات المعتمدة فقط، وتبقى حالة كل مشاركة ظاهرة لصاحب الحساب.

يسجل المشارك نوع البث أولاً (مباشر أو مسجل)، ثم يختار من البرامج المصنفة لذلك النوع، ويضيف رقم الحلقة واسم المشارك الآخر. مدد التسجيل المتاحة بفواصل ربع ساعة من 15 دقيقة إلى ساعتين. يضيف المسؤول البرنامج مع تحديد نوعه.

## الصلاحيات

- **الإدارة العليا:** حساب الدخول المحدد بمتغيرات البيئة؛ يراجع الطلبات، يدير البرامج والحسابات، يعيّن المراقبين، ويصدر الكشوف الشهرية.
- **المراقب:** حساب مقدم أو شيخ تنشئه الإدارة العليا ثم تغيّر صلاحيته؛ يراجع الطلبات ويعتمدها أو يرفضها.
- **المقدم أو الشيخ:** ينشئ حساباً عادياً، ويسجل المشاركات، ويشاهد سجل الشهر وحالة المراجعة والمستحقات المعتمدة الخاصة به.

توفر الإدارة العليا طباعة إجمالية مجمعة حسب البرنامج، وطباعة مفصلة تتضمن تاريخ البرنامج والتسجيل والمراجعة واسم المعتمد والتفاصيل المالية. الخطاب الرسمي يستخدم خطاً عربياً للطباعة الإدارية، ويظهر في ختامه «مدير قسم الإعلام» ثم «مجدي قدمور». تصدير Excel متاح بصيغة CSV متوافقة مع Excel.

## التشغيل

يتطلب Node.js 20 أو أحدث. ثبّت الحزم بالأمر `npm install` ثم شغّل الخادم بالأمر `npm start`.

في PowerShell:

```powershell
$env:ADMIN_USERNAME = "admin"
$env:ADMIN_PASSWORD = "ضع-هنا-كلمة-مرور-بطول-8-أحرف-على-الأقل"
npm start
```

افتح `http://localhost:3000`. دخول الإدارة يكون باسم المستخدم وكلمة المرور اللذين عيّنتهما. اسم المستخدم الافتراضي `admin`. ينشئ المقدمون والشيوخ حساباتهم من صفحة إنشاء الحساب.

تُحفظ الحسابات والطلبات في `data/records.json` على الخادم. احتفظ بنسخة احتياطية من هذا الملف، ولا تنشره للعموم. عند النشر على الإنترنت، استخدم HTTPS، وكلمة مرور إدارة قوية، واستضافة تحفظ مجلد `data` عند إعادة التشغيل.

## النشر للتجربة عبر GitHub وRender

ملف `render.yaml` يجهز الموقع كخدمة Node على Render. GitHub Pages لا يناسب هذا المشروع؛ لأن تسجيل الدخول والحسابات تحتاج إلى خادم.

1. أنشئ مستودعاً جديداً على GitHub، ثم ارفع ملفات المشروع إليه. لا ترفع كلمات المرور أو مجلد `data`.
2. في Render اختر **New → Blueprint** واربط حساب GitHub والمستودع. سيقرأ Render إعدادات `render.yaml`.
3. عند طلب قيمة `ADMIN_PASSWORD`، أدخل كلمة مرور الإدارة كـ **Secret** في لوحة Render؛ لا تكتبها في ملف أو مستودع GitHub. اسم المستخدم مضبوط على `MALEK` ويمكن تغييره من متغير `ADMIN_USERNAME`.
4. بعد اكتمال النشر، افتح رابط الخدمة الذي يعطيك إياه Render وشاركه مع زميلك للتجربة. يمكن دخول الإدارة باسم المستخدم وكلمة المرور المضبوطين، بينما ينشئ زميلك حساب مشارك من الصفحة.

**تنبيه للتجربة فقط:** إعداد Render المجاني يستخدم تخزيناً مؤقتاً؛ قد تضيع الحسابات والتسجيلات عند إعادة تشغيل الخدمة أو إعادة نشرها. لا تستخدمه لحفظ مستحقات حقيقية أو بيانات حساسة. للاستخدام الفعلي نحتاج تخزيناً دائماً وقاعدة بيانات ونسخاً احتياطية.

## سير العمل

1. ينشئ كل مقدم أو شيخ حساباً بصفته، ثم يسجل كل مشاركة باسمه والبرنامج والمشارك الآخر والتاريخ والمدة ونوع البث.
2. يراجع المسؤول الطلب ويعتمده أو يرفضه. الطلبات المعلقة والمرفوضة لا تدخل في الكشف.
3. يعرض كشف الإدارة مجموع المستحقات المعتمدة حسب الفترة، ويمكن تصديره بصيغة CSV المتوافقة مع Excel أو طباعته.

## حجز الاستوديو ومتابعة الحلقات

- الإدارة العليا تربط كل برنامج بحسابات الشيوخ والمقدمين المشاركين فيه. يظهر للمشارك فقط ما ارتبط بحسابه.
- يمكن للمقدم أو الشيخ تقديم طلب حجز لأحد اليومين القادمين لبرنامج مسجل فقط؛ لا يثبت الموعد إلا بعد تأكيد الإدارة العليا أو المراقب من لوحة المراجعة. تظهر الطلبات الجديدة مباشرة في قائمة الحجوزات المطلوب تأكيدها، ويُحجز وقتها مؤقتاً لمنع التعارض. التسجيل متاح من السبت إلى الخميس بين 1 ظهراً و7 مساءً، بفواصل 15 دقيقة، ولا يتجاوز مجموع حجوزات البرنامج ساعتين في اليوم.
- بعد انتهاء الموعد، يؤكد صاحبه إتمام التسجيل. يتحول الحجز إلى المراجعين، ولا يدخل في المستحقات إلا بعد الاعتماد. إذا لم يؤكد صاحبه، يبقى ظاهراً للمراجع لاتخاذ قرار بشأنه.
- يستطيع الشيخ اقتراح برنامج جديد للإذاعة أو القناة المرئية. ينشئ النظام خطاب Word موجهاً إلى مدير المحتوى، ويحفظه في الأرشيف تحت القناة والشهر؛ ويمكن للشيخ تنزيل الخطاب فور إنشائه.
- يرسل النظام إشعاراً بريدياً بطلبات الحجز إلى بريد الإدارة العليا والمراقبين المسجلين، كما تظهر الطلبات داخل لوحة المراجعة وتتحدث تلقائياً كل 30 ثانية أثناء فتح صفحة المراجعة. يتطلب البريد تسجيل عناوين الإدارة والمراقبين في إعدادات الحساب وضبط إعدادات SMTP الموضحة أدناه.
- المراقب أو الإدارة العليا يرفع تسجيل الحلقة بصيغة MP3 أو MP4، حتى 800 ميغابايت. الشيوخ والمقدمون المرتبطون بالحلقة يستطيعون تشغيل الملف وتنزيله. تحفظ نسخ الملفات السابقة عند استبدال الحلقة.
- يرسل الشيخ ملاحظة التعديل، وتكون مرئية لكاتبها والمراقبين والإدارة العليا فقط. بعد اعتمادها ينشئ النظام محضر Word ويحفظه في الأرشيف؛ ويمكن إرجاع الملاحظة للشيخ لاستكمالها وإعادة إرسالها.
- صفحة الأرشيف متاحة للإدارة العليا فقط، وتفصل مقترحات البرامج عن كشوف المستحقات ومحاضر Word، مع تصنيف الملفات حسب القناة والشهر، وتتيح تنزيل الملفات منفردة أو كحزمة ZIP للقناة المختارة.
- إعدادات الحساب تسمح بتحديث الاسم والهاتف والبريد وكلمة المرور مع التحقق بكلمة المرور الحالية. لا يمكن تغيير اسم المستخدم أو الصلاحية ذاتياً.

## تخزين Render والبريد

يستخدم الخادم `DATA_DIR` لتخزين ملف السجلات والوسائط والأرشيف. في الخطة المجانية يضبط `render.yaml` هذا المسار مؤقتاً على `/tmp/dar-al-ifta-radio-dues` حتى تعمل الخدمة دون قرص دائم؛ هذا التخزين مؤقت وقد تُحذف البيانات عند إعادة التشغيل أو إعادة النشر، فلا تستخدمه للمستحقات الرسمية. بعد ترقية الخدمة وإرفاق Persistent Disk في لوحة Render، غيّر `DATA_DIR` إلى `/var/data` وأرفق القرص على المسار نفسه. اختر سعة تكفي ملفات الفيديو، إذ قد يصل الملف الواحد إلى 800 ميغابايت. أقراص Render المدفوعة توفر لقطات يومية تلقائية يحتفظ بها Render سبعة أيام على الأقل؛ أنشئ كذلك نسخة احتياطية مستقلة دورية لأن الأرشيف داخل القرص نفسه ليس نسخة احتياطية منفصلة.

أضف إعدادات البريد التالية في Render **Environment**؛ لا تضع كلمات المرور في المستودع:

| المتغير | القيمة |
|---|---|
| `SMTP_HOST` | خادم SMTP لمزود البريد |
| `SMTP_PORT` | المنفذ، غالباً `587` |
| `SMTP_SECURE` | `false` للمنفذ 587 أو `true` لاتصال TLS مباشر |
| `SMTP_USER` | اسم مستخدم SMTP |
| `SMTP_PASSWORD` | كلمة مرور التطبيق/SMTP كـ Secret |
| `SMTP_FROM` | عنوان المرسل المسموح به لدى المزود |

إذا لم تضبط SMTP أو لم يضع المراقبون عناوين بريدهم، يحفظ النظام الحجز لكنه يعرض تحذيراً بأن رسالة البريد لم تُرسل.
